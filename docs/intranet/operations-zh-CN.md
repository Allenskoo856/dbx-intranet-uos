# DBX 内网使用与运维手册

## 日常使用

1. 从桌面菜单启动 DBX。
2. 在“连接”中填写数据库地址、认证方式和超时；优先使用内网域名/IP，避免把公网数据库写入配置。
3. 在“设置 > 驱动管理”查看本机已安装驱动。需要新增驱动时，使用经过签名或 SHA256 校验的离线包导入，不点击在线安装/升级。
4. AI 功能只有在配置了可达的内网模型服务或本地 Ollama 时才可用；没有模型服务时，数据库连接和 SQL 编辑功能仍可独立使用。
5. MCP Server 使用已预置并经管理员批准的本地运行时。离线包不会从 npm Registry 安装或升级 MCP Server。

## 备份和迁移

备份前关闭 DBX，按企业数据分级制度保存用户数据目录、连接配置、历史记录和本地驱动目录。迁移到另一台内网机器时，同时传输版本对应的 `.deb`、`SHA256SUMS`、依赖包清单和离线驱动包；不要只复制可执行文件。

## 排障顺序

### 程序无法安装

```bash
dpkg --audit
dpkg-deb --info DBX_<version>_uos1070-webkit40_amd64.deb
```

重点检查架构是否为 `amd64`，以及本分支的 `libwebkit2gtk-4.0-37`、JSC 4.0、libsoup2、GTK 和 AppIndicator 依赖是否由批准的软件源提供。不要用公网 apt 源补依赖。

### 程序安装成功但启动失败

先在终端运行 `/usr/bin/dbx --dbx-offline-self-test`。如果自检通过而 GUI 失败，收集 UOS 版本、桌面环境、WebKitGTK 包版本和 DBX 日志；不要上传连接密码、Token、私钥或完整连接字符串。

### 驱动连接失败

确认驱动包已完整导入、Java/JRE 路径有效、驱动版本与数据库类型匹配，并检查数据库端口和证书。离线模式下“自动安装驱动失败”是预期行为，应改用离线导入。

### AI 或 MCP 不可用

确认配置的 endpoint 是内网可达地址、证书和代理符合企业策略，并检查本地 MCP/Node 运行时是否由管理员预置。离线模式不会访问 GitHub、R2、npm Registry 或公共 Agent Registry 来补齐缺失组件。

## 支持信息

提交问题时提供 DBX 包版本、`dpkg-deb --info` 输出、`--dbx-offline-self-test` 输出、UOS 版本、WebKitGTK 版本和脱敏日志。任何网络抓包都应按企业审批流程进行；不要把用户数据目录或密钥直接打包上传。
